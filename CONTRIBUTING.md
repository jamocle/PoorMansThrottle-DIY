# Contributing to Poor Man's Throttle

Poor Man's Throttle (PMT) is a proprietary, closed-source project. The PMT
application and firmware source code is not publicly distributed.

Community feedback is welcome, but code contributions are accepted only from
contributors who have been vetted and approved by the project owner.

## Ways Anyone Can Help

You do not need source-code access to:

* report bugs
* suggest features or improvements
* provide hardware compatibility information
* provide testing results
* suggest documentation corrections
* contribute locomotive or other supported audio content under the applicable
  content terms

Please open a GitHub issue first when proposing a software or firmware change.
This allows the idea, scope, and expected behavior to be discussed before any
private source access is considered.

## Becoming a Code Contributor

Code-contributor access is invitation-based and is not automatic.

The project owner may consider contributor access after reviewing the proposed
work and the prospective contributor. Approval is discretionary and may be
limited to a particular feature, component, or period of time.

Before receiving private PMT application or firmware source code, an approved
contributor must:

1. complete the PMT Contributor License Agreement (`CLA.md`);
2. complete any confidentiality or nondisclosure agreement required by the
   project owner;
3. agree to keep private source code and private project materials
   confidential;
4. use source access only for the approved PMT contribution work; and
5. follow the repository, review, testing, and submission process specified by
   the project owner.

Source access may be revoked when it is no longer needed or if the applicable
agreements or project requirements are not followed.

## Contribution Review

Approval to access source code does not guarantee that a contribution will be
accepted.

The project owner retains final control over:

* project direction and architecture
* which contributors receive source access
* which proposed changes are accepted
* how accepted contributions are modified or integrated
* release timing
* licensing of PMT releases
* branding and official distribution

Contributions should be focused on the approved objective and should avoid
unrelated refactoring or behavior changes.
