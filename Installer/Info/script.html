Scripting

PMT now supports autonomous scripting.

Scripting makes it possible to run the train autonomously through scripted commands. The scripting language is continuing to expand, allowing for more and more logic over time.

How to access the script page

From the throttle terminal, press and hold the Send button. A normal tap sends the current command, but a long-press opens the dedicated script page where larger scripted sequences can be entered and run.

The script page is intended for more than one-off commands. It provides a place to enter a sequence of instructions that can direct train behavior automatically, helping reduce repetitive manual control when a repeatable flow is needed.

Step 1 Open the throttle terminal and locate the Send button.
Step 2 Long-press Send to open the Run Script page.
Step 3 Enter the script in the editor area.
Step 4 Run the script to let the train follow the scripted command sequence.
Scripting is designed for autonomous control through commands, and the language is growing over time to support increasingly capable logic and more advanced scripted behavior.

As the language expands, scripting becomes more useful for creating repeatable train actions, more structured command sequences, and richer control flows without requiring every step to be handled manually in real time.

Firmware recorded scripts

PMT firmware also has an SD-backed script recorder/player. This is separate from the app's Run Script page: app terminal scripts are entered and interpreted by the app, while firmware scripts are stored on the device as /scripts/<name>.pmt and are played by the firmware.

Two different script systems: the app's Run Script page and firmware-resident .pmt playback are related tools, but they are not the same scripting engine. Firmware .pmt files use recordable device-control commands plus PAUSE <milliseconds>.
SR Start recording eligible external control commands and their timing.
SR0 Stop recording now and hold the unsaved recording in the SAVE state.
SR=<name> Save the pending recording as /scripts/<name>.pmt. It can also still directly stop-and-save an active recording.
SRX Discard the pending unsaved recording and return to IDLE.
SP1=<name> Play a saved firmware script once.
SPR=<name> Play a saved firmware script repeatedly.
SP0 Stop active firmware script playback.
SS? Query script state: IDLE, REC, SAVE, PLAY, or REPEAT.
SD=<name> Delete a saved firmware script when no recording, pending save, or playback is active.
SA=<name>,±<ms> / SA=±<ms> Adjust the script's total pause time and save it automatically. Negative milliseconds shorten the script; positive milliseconds lengthen it. The no-name form targets the currently playing script.

Throttle app firmware-script floater

  • The firmware-script floater is on the Throttle screen and reflects the current firmware state when opened.
  • Play requests the saved script list through PX/1 ScriptList. Each script row lets the user choose one-shot playback (SP1=<name>) or repeat playback (SPR=<name>).
  • The < chevron in the script-list state cancels the selection and returns to the normal Play/Record controls.
  • Record sends SR. Stop sends SR0, so recording stops immediately and firmware reports A:SS=SAVE while the app asks for a name.
  • In the SAVE state, Save sends SR=<name>. The < chevron sends SRX to discard the unsaved recording.
  • While a script is playing or repeating, the floater shows a millisecond adjustment field plus vector speed controls. Speed Up (up arrow) sends SA=-<ms> to shorten total pause time. Slow Down (down arrow) sends SA=+<ms> to lengthen total pause time. The current cycle is not interrupted; repeat playback uses the saved adjustment on the next cycle.
  • Closing the floater does not stop active recording or playback and does not discard a pending save. Reopening the floater queries firmware state so the controls match what the device is actually doing.

Adjusting firmware-script timing

Firmware revision 242 adds SA (Script Adjust). Use SA=<name>,-<ms> to shorten a saved script or SA=<name>,+<ms> to lengthen it. During active playback, the shorter forms SA=-<ms> and SA=+<ms> target the currently playing script. A successful adjustment returns ACK:SA.

  • Firmware normalizes the requested timing change across the script's existing PAUSE positions and saves the adjusted .pmt file automatically.
  • If a reduction consumes all available pause time, firmware writes the existing positions as PAUSE 0 instead of deleting them. This preserves where a later positive adjustment can add time back.
  • If all saved pause positions are already PAUSE 0, positive time is distributed across those retained positions. If a script has no pause positions at all, a positive adjustment is added as a trailing pause.
  • A one-shot script already in progress finishes its current run unchanged. A repeating script keeps its current cycle unchanged and applies the adjusted content at the next repeat boundary.
  • The adjustment must include an explicit plus or minus sign and a non-zero millisecond magnitude from 1 through 2147483647. Invalid values return ERR:VALUE.

Recording stop and naming

The current app stops recording with SR0 before asking for a script name. This captures the final recorded pause at the moment Stop is pressed. Time spent typing the name is not added to the script. While the unsaved recording is waiting for a name, SS? reports A:SS=SAVE.

Playback control rules

  • Script-generated commands use the normal device command handlers.
  • External/app-originated recordable control commands are ignored while firmware script playback is active so they cannot unexpectedly override the script.
  • Firmware-internal and scheduled control commands are not blocked by script playback; they continue to apply normally.
  • An external/app-originated S is a deliberate exception: it stops script playback first, then executes the throttle's normal stop behavior.
  • An S inside the script stops the train normally but does not terminate the script. Playback continues with the following pause or command.

Grace shutdown: G0 and G1

  • G1 enables grace shutdown. If a disconnect starts the grace countdown while a firmware script is running, the script continues normally during the countdown.
  • If the connection returns before grace expires, the countdown is cancelled and the running script continues; it is not restarted.
  • If grace actually expires, firmware stops active script playback before continuing with the device's existing grace-expiry shutdown behavior.
  • G0 disables grace shutdown and clears any active grace countdown. It does not stop a running script.

Repeat timing

Firmware playback uses an absolute logical timeline. Each PAUSE advances that timeline instead of starting a new delay from the moment the firmware loop happens to process it. Small command-processing delays or loop jitter therefore do not accumulate into repeat-cycle drift.

In repeat mode, firmware rewinds the script content without resetting the logical clock to the current time. A trailing pause recorded when recording stops with SR0 (or the compatible direct SR=<name> form) is honored before the next iteration starts.
