NEW CAPABILITY — REST & HTTP COMMUNICATION

The World is Your Oyster.

Poor Man’s Throttle can now communicate RESTfully with HTTP endpoints, connecting your railroad to a much bigger world. Smart-home devices, web services, layout accessories, automation systems, and your own custom endpoints can now become part of the PMT ecosystem.

Your railroad no longer has to live in its own little world.

PMT already controls locomotives, layout devices, physical throttles, automation, and mesh-connected hardware. REST and HTTP support take the next step by letting PMT talk to systems outside the railroad itself.

OUTBOUND CONTROL

PMT can trigger outside services

A PMT action can call an HTTP or REST endpoint and cause something outside the throttle ecosystem to happen: turn on a smart light, trigger a home automation routine, send a command to another controller, or call your own web service.

CONNECTED LAYOUT

Bring outside systems into the experience

The railroad can now interact with devices and services that already speak HTTP. That means your layout can become part of a broader smart-home, automation, or custom-control environment instead of being isolated from it.

If a service exposes an HTTP endpoint, PMT now has a path to talk to it.

What would you actually use this for?

The possibilities range from practical to theatrical. The value is that PMT can now reach beyond railroad-specific hardware.

SMART LIGHTING

Govee and other smart lights

Tie room lighting or layout lighting to railroad events. Dim the room when an operating session begins, change colors for a nighttime scene, or trigger special lighting effects when a train reaches a certain point.

VOICE & SMART HOME

Alexa and home automation

Use PMT actions as part of a larger smart-home workflow. Trigger routines, announcements, lighting scenes, or other supported automation through the services you already use around the house.

CUSTOM SERVICES

Your own REST endpoints

If you run a local web service, Raspberry Pi, home server, Node-RED flow, or custom controller, PMT can call into it and make it part of the layout.

LAYOUT EFFECTS

Coordinate scenery and accessories

Use HTTP calls to trigger building lights, fans, animated scenery, sound systems, signage, signals, or other controllers that are not directly wired into PMT.

WEB AUTOMATION

Connect to cloud or local services

Send events to local or remote endpoints for logging, dashboards, notifications, automation, or integrations with services that already understand web requests.

BRIDGE SYSTEMS

Make unlike systems cooperate

REST can act as the common language between PMT and another ecosystem. One system does not need to know how PMT works internally — it only needs an endpoint.

Real-world ideas

Here are a few examples of how REST and HTTP can make an operating session feel more polished, automated, and alive.

1

Start an evening session

Tap a PMT control and have Govee room lights dim, layout lights come on, and a nighttime color scene activate automatically.

2

Trigger an announcement

Have a PMT event call a service that plays a station announcement, activates a smart speaker, or starts a custom audio sequence.

3

Coordinate arrival effects

When a train enters a scene, trigger structure lighting, animated accessories, ambient audio, or another local controller through an HTTP call.

4

Send operating data elsewhere

Push events to your own dashboard, logging system, web service, or automation engine so the rest of your technology can react to the railroad.

REST support is powerful because it is not tied to one brand or one type of hardware. It gives PMT a common way to reach almost anything that understands HTTP.

Local or global. Simple or ambitious.

Your endpoint can live on the same network as the layout or somewhere farther away, depending on the service and how you choose to configure it.

LOCAL

Keep everything on your own network

Call a local controller, server, automation hub, Raspberry Pi, or custom application without needing to involve a cloud service.

GLOBAL

Reach services beyond the layout

Where appropriate, PMT can also communicate with reachable remote endpoints, opening the door to broader web-based integrations and services.

Start with something simple, like turning on a light. Then keep going. Once PMT can speak HTTP, the number of things it can interact with grows dramatically.

This is bigger than another feature.

REST and HTTP communication make PMT extensible beyond the hardware that ships with the project. You do not have to wait for a dedicated PMT integration every time you want to connect something new.

That is the exciting part: the ecosystem can now reach outward. Your railroad can talk to smart-home gear, custom software, local servers, automation platforms, web APIs, and devices that were never originally designed with model railroading in mind.

The world really is your oyster. If you can expose it through REST or HTTP, you can start imagining how it belongs in your railroad.
