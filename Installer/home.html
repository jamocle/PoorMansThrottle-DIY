What is PMT? Poor Man’s Throttle is a completely FREE DIY wireless train control system that lets you run DC and dead-rail (Battery) locomotives from your phone using inexpensive ESP32-based hardware. Build it yourself, tune it yourself, and keep your railroad open, affordable, and fun.

FAQ (Frequently Asked Questions)
I'm new to this. Where should I start?

Start with the Getting Started with Poor Man's Throttle page. It brings the hardware, installation choices, firmware, app, sound, and reference material together in one place.

For your first PMT build, take it in this order:

  1. Decide how you want to use PMT. Choose the installation style that fits your railroad:
    • PMT between the transformer and track — no locomotive modifications.
    • PMT inside the locomotive using track power.
    • Dead Rail / battery powered.
  2. Start with the basic PMT recipe. A basic locomotive controller needs:
    • an ESP32 controller
    • a regulated 5V power supply
    • a motor driver
    Sound, battery monitoring, lighting, and other features can be added after the basic system is working.
  3. Choose hardware that fits your locomotive. Consider the available space, motor voltage, and motor current when choosing the ESP32 and motor driver.
  4. Install the PMT firmware and app. Flash the correct firmware for your ESP32 board, install the PMT app on your phone or tablet, and verify that the app can find the PMT device.
  5. Follow the installation guide for your motor driver. Wire and test the basic motor-control system before adding optional features.
  6. Get the locomotive running first. Once speed, direction, stop, and braking work correctly, add the extras you want—sound, lights, battery monitoring, automation, physical controls, WiFi, and so on.

You do not need to understand CVs, Terminal commands, automation, or advanced configuration before building your first basic PMT system. The project is designed so you can start simple and add features later.

What are the basic parts required for an installation of PMT including sound?

A basic PMT installation with sound has three main parts for controlling the locomotive, plus the audio hardware:

  • ESP32 controller — the brains of PMT.
  • 5V power converter — supplies the ESP32 with the power it needs.
  • Motor driver — controls power to the locomotive motor.
  • I2S audio amplifier — such as a MAX98357A, to produce the sound.
  • Speaker — connected to the audio amplifier.
  • microSD card — stores the locomotive sound files.

Some ESP32 boards also require a separate microSD card reader. The ESP32-S3-CAM version has a built-in microSD slot, so it does not need the separate reader.

More information: Full Hardware Recipe · PMTPlayer Audio Installation Guide

I don't need sound. What are the basic parts required for an installation of PMT without sound?

If you do not want sound, a basic PMT installation only needs three main electronic components:

  • ESP32 controller — the brains of PMT.
  • 5V power converter — provides the correct power for the ESP32.
  • Motor driver — controls the locomotive motor. Choose one that is suitable for the motor and current requirements of your installation.

Your locomotive's motor and battery or other power source connect to these components, but they are not additional PMT electronics.

You do not need the audio amplifier, speaker, or microSD card used for a sound installation. Sound can always be added later.

What options are available for locomotive power, and what are some tips and tricks?

PMT supports several different ways to power and control a locomotive. You do not have to convert everything to battery power.

Power arrangement How it works Good choice when…
PMT between transformer and track Transformer → PMT → Track → Locomotive You want wireless control of existing unmodified DC trains.
PMT inside locomotive using track power Track → locomotive pickups → PMT → motor You want individual locomotive control while keeping powered rails.
Dead rail / onboard battery Battery → PMT → motor You want the locomotive completely independent of track power.
Track + battery hybrid Track remains powered for cars/accessories, but locomotive motor uses its own battery and PMT You want battery-powered locomotive control while still using track power for lights and accessories.

1. Transformer → PMT → Track

This is usually the simplest way to modernize a traditional DC layout.

Transformer → PMT Controller → Track → Locomotive

The supplied PMT guide recommends leaving the transformer at a constant full output and letting PMT control the track using PWM.

Advantages include:

  • no locomotive modifications
  • wireless phone control
  • works well when locomotive space is limited
  • easy way to convert an existing DC layout

Tip: The PMT controls the entire powered track section, so locomotives on that section receive the same controlled track power.

2. PMT inside the locomotive with track power

Here the rails remain powered, but the PMT electronics are installed inside the locomotive.

Track → Pickups → PMT → Motor

This allows individual locomotive control, even when several locomotives share powered track.

It is also useful when you want the rails to continue powering things such as passenger-car lighting or layout accessories.

3. Dead rail — onboard battery

With dead rail, the rails do not provide propulsion power.

Battery → Fuse → PMT → Motor

The locomotive carries its own battery and PMT electronics.

This gives you:

  • no dependence on clean rail for motor power
  • independent control of multiple trains
  • operation where electrical pickup is unreliable
  • a completely self-contained locomotive

The electronics can be placed in the locomotive, tender, or even a dedicated battery car if space is limited.

4. Track power + onboard battery

PMT also documents a hybrid arrangement.

The locomotive motor is isolated from the rails and runs from its onboard battery, while the rails remain powered for things such as:

  • passenger-car lighting
  • buildings
  • accessories
  • other traditional track-powered equipment

This can give you much of the freedom of dead rail without giving up useful powered-track infrastructure.

Useful power tips

  • Use a fuse. The supplied build guide recommends appropriate overcurrent protection in the main motor-power path.
  • Don't power the ESP32 directly from locomotive voltage. Use a regulated 5V power module for the ESP32.
  • Use a buck converter when necessary. If your battery voltage is higher than you want the locomotive motor to receive, use a buck converter in the motor-power path.
  • Match the power source to the motor. Do not assume that a higher-voltage battery is automatically better. Choose the voltage appropriate for your locomotive, motor, and installation.
  • Battery monitoring is optional. Adding an INA219 lets PMT report voltage, current, and power and optionally provide low-voltage warning, throttle limiting, and shutdown protection.
  • Think about where the hardware will fit before choosing the power method. PMT electronics can be placed in the locomotive, tender, battery car, external enclosure, or trackside controller box depending on the installation.

Example buck-converter arrangement:

20V battery → buck converter → about 15V → motor driver

Adjust the buck converter with a multimeter before connecting the motor driver.

For a small locomotive with little internal room, PMT between the transformer and track may be much easier than putting a battery and electronics onboard.

I just want to use PMT to power my old train set with no locomotive modifications. How can I do that?

If you have a traditional DC track-powered train set, you can install PMT completely outside the locomotive.

Place the PMT controller between your transformer and the track:

Transformer → PMT Controller → Track → Locomotive

The transformer supplies the power, while PMT controls the power going to the rails. Your locomotive remains unchanged and simply picks up its power from the track as it always has.

A small project box can hold the PMT electronics, such as the ESP32, motor driver, fuse, and wiring terminals. This makes the system easy to install or remove without modifying your trains.

One thing to remember: PMT controls the powered section of track, so any locomotive on that same powered section receives the same track power.

More information: PMT Power Configuration Guide · Installation Options — Trackside DC Controller Box

Can I use Track Power to power PMT? What does that look like?

Yes. PMT can be installed inside the locomotive and powered from the track.

In this setup, the track is kept at a constant voltage from your transformer. The locomotive's existing track pickups bring that power into PMT.

Track Power → Locomotive Pickups → PMT Electronics → Motor

PMT then controls the locomotive's motor instead of varying the voltage on the track. A 5V power module is used to provide the correct power for the ESP32, while the motor driver controls the locomotive motor.

Because the track stays powered, it can also continue supplying power to things such as lights, buildings, and other accessories.

If each locomotive has its own PMT controller, multiple PMT-equipped locomotives can be controlled independently while sharing the same powered track.

How do I install Dead Rail/Battery powered PMT?

With a Dead Rail installation, the locomotive carries its own battery and does not depend on the rails for power.

A basic installation looks like this:

Battery → Fuse → Motor Driver → Locomotive Motor

The same battery also feeds a 5V power module, which supplies the correct power to the ESP32:

Battery → 5V Power Module → ESP32

If the battery voltage is too high for your locomotive motor, an optional buck converter can be placed before the motor driver to reduce the voltage.

The battery and PMT electronics can be installed inside the locomotive, in a tender, or in a battery car, depending on how much space you have.

With true Dead Rail operation, the rails do not need to be powered. Each PMT-equipped locomotive carries its own power source and can be controlled independently.

I have an ESP32-S3-CAM board (N16R8) with dual USB-C inputs. Does it matter which input I connect to?

The ESP32-S3-CAM N16R8 board used in the PMT hardware examples has two USB-C connectors, but PMT does not assign a specific left/right connector for every board variant.

For installing or updating firmware, use the USB-C port that provides a USB data/serial connection to your computer. Use a known-good USB data cable, not a charge-only cable. When connected correctly, the ESP32 should appear as a selectable USB/serial device in the PMT firmware installer.

For normal PMT operation, the ESP32 needs a clean, regulated 5V supply.

Important: Dual-USB ESP32-S3-CAM boards are not all wired identically. One connector may be intended for native USB and the other for a USB-to-serial interface. Check the labels printed next to the connectors or the information for your exact board before assuming the two ports are interchangeable.

What SD card size should I use and how should I format it for use with PMT?

PMT does not require a large microSD card. A small card is fine — even 128 MB is enough for a typical PMT sound installation.

The important part is formatting the card correctly:

  • 128 MB through 2 GB: format as FAT16.
  • 4 GB through 128 GB: format as FAT32.
  • Do not use exFAT.

Be especially careful with 64 GB and 128 GB cards. They are often sold already formatted as exFAT, so they must be reformatted to FAT32 before PMT can use them.

If you are buying a card specifically for PMT, there is generally no need to buy a very large one.

How do I tell if my IBT-2 Motor Driver is good or bad?

You can bench-test the IBT-2 with a 12V power source, a separate 5V logic source, and a small DC motor.

With the board powered correctly and both enable pins turned on, test one direction at a time:

  • RPWM HIGH / LPWM LOW — the motor should turn one direction.
  • RPWM LOW / LPWM HIGH — the motor should turn the opposite direction.

The results are simple:

  • Motor runs both directions: the IBT-2 is good.
  • Motor runs in only one direction: one side of the IBT-2 is bad.
  • Motor runs in neither direction: check the wiring and power before assuming the board is bad.

Before condemning the board, make sure VCC is 5V, the grounds are connected together, R_EN and L_EN are HIGH, and the motor and power supply are known to be good.

Important: Do not put 12V into the IBT-2's VCC logic pin.

More information: IBT-2 Quick Test · IBT-2 Test Video

How do I determine what Motor Driver Type I should use for my Motor Driver?

The Motor Driver Type tells PMT how to control the inputs on your motor driver board. It does not describe how much voltage or current the board can handle.

For the motor drivers shown on the PMT Getting Started page, use:

Motor Driver PMT Motor Driver Type
BTS7960 / IBT-2 DUAL_PWM
L298N PWM_BIDIR
TB6612FNG PWM_BIDIR
L9110S DUAL_INPT

If your motor driver is not listed, look at the labels on its control pins:

  • RPWM + LPWM → DUAL_PWM
  • PWM + DIR → PWM_DIR
  • PWM/EN + IN1 + IN2 → PWM_BIDIR
  • IN1 + IN2 only → DUAL_INPT

For a TB6612FNG, use its dedicated PWM input plus its two direction inputs, and hold STBY HIGH so the driver is enabled.

Choosing the wrong Motor Driver Type can keep the motor from running correctly even when the power wiring is correct. Choosing the type is also separate from making sure the board has enough voltage and current capacity for your locomotive.

What is Start Assist / Kick, when would I need to use it and how?

Start Assist, also called Kick, gives the motor a brief extra push when the locomotive begins moving from a stop.

Some motors need more power to start turning than they need once they are already moving. Without Start Assist, you may raise the throttle and see the locomotive hesitate, hum, or suddenly jump into motion.

When should I use it?

Start Assist may help if:

  • the locomotive hesitates when starting at low speed;
  • the motor needs extra power to break away from a stop; or
  • you have adjusted Minimum Start Throttle, but starting is still inconsistent.

If your locomotive already starts smoothly, you generally do not need Start Assist.

How do I configure it?

In the PMT app, open:

Configuration → Motor & Drive Behavior

Use the Start Assist / Kick settings there to tune how much help the motor receives when starting.

This is the recommended way to adjust it because the Configuration screen handles the underlying settings for you.

Behind the scenes, Start Assist is stored in CV9 — Kick Configuration:

CV9=<throttle>,<ms>,<rampDownMs>,<maxApply>

The documented default is:

CV9=0,0,80,15

So you normally do not need to manually edit CV9. The Motor & Drive Behavior screen changes the CV9 configuration behind the scenes.

Start Assist vs. Minimum Start Throttle

  • Minimum Start Throttle sets the minimum useful motor-output level when the locomotive is moving.
  • Start Assist / Kick provides a temporary boost to help the motor get started from a stop.

A good approach is to set Minimum Start Throttle first, then add a small amount of Start Assist only if the locomotive still has difficulty beginning smoothly.

I do not see a battery icon on my PMT screen. How do I get it to show up and monitor my battery?

PMT's battery icon appears when INA219 battery monitoring is installed and active.

The INA219 is a small sensor board that lets PMT measure:

  • battery voltage
  • current draw
  • power usage
  • low-voltage conditions

What do I need?

Install an INA219 current/voltage monitor in the battery power path and connect its I²C SDA and SCL lines to the ESP32.

The INA219 must be installed in series with Battery +:

Battery + → INA219 → PMT power input

Your existing PMT wiring otherwise stays in place.

How do I enable it?

After the INA219 is wired correctly, open Configuration → Battery Management.

Enable the INA219 battery monitor there.

Behind the scenes, this enables:

CV30=1

Battery monitoring is disabled by default, so the battery indicator will not appear until the sensor is installed and monitoring is enabled.

Once the INA219 is active and sending telemetry, the throttle screen can show a battery indicator button near the status area.

Tap the battery button to open the Battery Telemetry drawer and view live battery information.

Can PMT protect the battery too?

Yes. Battery Management also provides optional settings for:

  • low-voltage warning
  • throttle limiting
  • low-voltage shutdown
  • recovery voltage
  • battery-disconnect detection
  • optional low-voltage indicator LED

Those protection thresholds should be configured for the battery chemistry and cell count you actually use. You do not need to enable the protection thresholds just to view battery telemetry.

If the INA219 is installed and enabled but the icon still does not appear, verify its SDA/SCL wiring, I²C address, power, and sensor detection.

More information: INA219 Battery Management · PMT INA219 Battery Monitor Installation Guide

How do I control LED lights?

PMT can control LED lights directly from the ESP32 using its Output Controls.

For each light, you configure:

  • Name — such as Headlight, Reverse Light, or Ditch Light.
  • Pattern — for example Solid, Blink, Ditch Light, Strobe, or other lighting effects.
  • GPIO Pin — the ESP32 output pin connected to that light.
  • Direction — Both, Forward, or Reverse.

For example, a headlight can be configured as LED Solid / Forward, while a rear light can be LED Solid / Reverse. PMT will then only operate each light in the appropriate direction.

PMT supports up to 12 firmware FX outputs, so you can configure several independent lights and effects.

LEDs connected directly to an ESP32 GPIO must use an appropriate series resistor, because the GPIO output is 3.3V. Each independently controlled LED output should also use its own GPIO pin.

More information: Lighting and Auxiliary Outputs · Output Control User Guide · Wiring Reference

How would I go about adding a headlight and/or reverse headlight?

PMT can control a forward headlight, a reverse light, or both using Output Controls.

Wiring

Configured ESP32 GPIO → series resistor → LED → GND

PMT's ESP32 GPIO outputs are 3.3V, so the LED should use a series resistor. The supplied lighting guide recommends a practical 100Ω–220Ω range for direct GPIO indicator use.

Do not reuse the firmware's onboard status LED pin for an accessory light.

Configure a forward headlight

Open Configuration → Output Control, then add an output with:

  • Name: Headlight
  • Pattern: LED Solid
  • GPIO Pin: the GPIO connected to the LED
  • Direction: Forward
  • Momentary: Off

With the control turned on, PMT will allow the light to operate when the locomotive is selected Forward and suppress it when direction changes to Reverse.

Configure a reverse headlight

Add another Output Control:

  • Name: Reverse Light
  • Pattern: LED Solid
  • GPIO Pin: a different GPIO
  • Direction: Reverse
  • Momentary: Off

This light is allowed when the locomotive is in Reverse.

Using both together

PMT supports up to 12 firmware FX slots, so the forward and reverse lights can be separate outputs.

Function Default direction Classic ESP32 default pin ESP32-S3 default pin
Headlight / FX1 Forward GPIO4 GPIO15
Reverse Light / FX2 Reverse GPIO5 GPIO16

Those are firmware defaults, not mandatory pins. The actual GPIO can be changed in configuration as long as it is a valid, non-conflicting output pin.

Recommended: use one Headlight button for both lights

PMT's Linked FX feature lets one visible Output Control operate a second Output Control at the same time. When a control is used as a Linked FX target, it is hidden from the normal standalone Output Control button list.

Configure the two outputs like this:

  • Headlight
    • Pattern = LED Solid
    • GPIO = forward headlight GPIO
    • Direction = Forward
    • Momentary = Off
    • Linked FX = Reverse Light
  • Reverse Light
    • Pattern = LED Solid
    • GPIO = reverse headlight GPIO
    • Direction = Reverse
    • Momentary = Off

Because Reverse Light is the Linked FX target, it is hidden from the normal throttle Output Control list. You see just one Headlight button.

Forward selected → Headlight ON, Reverse Light OFF
Reverse selected → Headlight OFF, Reverse Light ON

Both FX are switched together logically, but each light's own Direction setting determines which physical LED is allowed to illuminate.

The supplied lighting documentation also notes that Headlight and Reverse Light are linked by default, providing this paired directional-light behavior without requiring two separate user-facing buttons.

What patterns exist for LED lights and what do they mean?

PMT provides several built-in LED patterns that you can select in Output Control.

Pattern What it does
LED SolidStays steadily ON while active.
LED Double BlinkTwo short flashes, then a pause.
LED FREDA FRED-style sequence: a single flash followed by a closely spaced double flash.
LED Blink +User-configurable blink timing.
LED Blink -Same blink timing as +, but shifted half a cycle so two lights can alternate.
LED Ditch +Built-in ditch-light pulse.
LED Ditch -Same ditch-light pulse, shifted half a cycle for alternating ditch lights.
LED Strobe +Repeating double-strobe burst.
LED Strobe -Same strobe pattern, shifted half a cycle.
LED Rotary +Smooth rise-and-fall effect like a rotating beacon.
LED Rotary -Same rotary effect running opposite the + version.
LED Mars +Smooth brightness sweep that imitates a Mars light.
LED Mars -Same Mars effect, shifted half a cycle.
LED Gyralite +Smooth Gyralite-style brightness pulse.
LED Gyralite -Same Gyralite effect, shifted half a cycle.

means a 1000 ms total cycle with the LED ON for 250 ms. The - version starts half a cycle later.

Each LED pattern uses a firmware FX slot and a GPIO pin, and can be restricted by Direction to Both, Forward, or Reverse.

How do I turn off the LED on my ESP32?

PMT controls the ESP32's onboard status LED with CV21 — Onboard LED Output Gate.

You have three choices:

  • CV21=0 — keep the onboard status LED off all the time.
  • CV21=1 — normal behavior. PMT controls the LED using its normal colors and blink patterns. This is the default.
  • CV21=2 — keep the LED off while PMT is connected by Bluetooth or WebSocket, but allow the normal LED indication when it is disconnected.

For most people who simply want the ESP32 light turned off, use:

CV21=0

You can change CV21 from the app's Configuration Variables screen, or from the Terminal.

To check the current value:

CV21?

To turn the onboard LED off:

CV21=0

To restore normal LED behavior later:

CV21=1

If you want the status LED available for troubleshooting when disconnected, but dark during normal operation, use:

CV21=2

This setting only gates the firmware-controlled onboard status LED. It does not disable LEDs that you have configured separately as PMT Output Controls.

How do I get sound to work?

To use PMTPlayer sound, you need an I2S audio amplifier, speaker, and microSD card along with your ESP32.

The basic setup is:

  1. Connect the audio amplifier and speaker using the wiring for your specific ESP32 board.
  2. Prepare the microSD card using FAT16 or FAT32 — not exFAT.
  3. Download PMTPlayer sounds and copy the WAV files into the correct folder on the card:
    • /diesel/ for Diesel sounds
    • /steam/ for Steam sounds
  4. Insert the microSD card and power up PMT.
  5. Enable audio and select Diesel or Steam.

PMT audio is disabled by default, so a completely correct installation can still be silent until audio is turned on.

If you use an ESP32-S3-CAM, the microSD slot is built into the board. Other supported ESP32 boards require a separate microSD reader.

If it still does not play sound, the PMTPlayer Audio Installation Guide includes wiring checks, SD-card checks, and startup troubleshooting.

I just hooked up my SD reader (WWZMDiB) and when I turn on Audio in the app my PMT crashes. What could be wrong?

If you are using the WWZMDiB Micro SD TF Card Adapter Reader Module, the SD reader itself may be causing the problem.

This particular module contains an AMS1117 voltage regulator. The hardware information for this reader states that the board should be powered with 5V as supplied.

If you want to operate the reader from 3.3V, the documented modification is to bypass the AMS1117 regulator by soldering its Vin and Vout pins together, as shown below.

However, simply changing between 5V and 3.3V did not solve the problem reported by the Poor Man's Throttle Forum member who discovered this issue. The original poster specifically reported:

“The original board kept crashing my ESP boards (standard and s3 both) using both 5v and 3v3 pins. Doing this fixed my problems.”

In other words, the poster experienced crashes with both the Standard ESP32 and ESP32-S3, and reported the problem while trying both the 5V and 3.3V pins. The reported fix was to make the Vin-to-Vout solder bridge on the AMS1117 regulator and then operate the modified reader from 3.3V.

What are the different default sounds I can control and how do I configure them?

PMT provides three built-in sounds that you can add directly to your Output Control panel:

Sound Pattern Recommended setup What it does
Bell Audio Bell Direction = Both, Momentary = Off Tap once to turn the bell on. Tap again to turn it off.
Horn Audio Horn Direction = Both, Momentary = On Hold the button to sound the horn. Release it to stop.
Cab Chatter Audio Cab Chatter Usually left ON when you want chatter active Plays a chatter sound, then automatically schedules additional chatter at random intervals.

How do I add one?

Open Configuration → Output Control.

  1. Tap Add Output.
  2. Enter a name, such as Bell, Horn, or Cab Chatter.
  3. Choose the matching Pattern.
  4. Set Direction to Both, Forward, or Reverse as needed.
  5. Set Momentary appropriately.
  6. Save the configuration.

You do not enter an Audio Track number for the built-in Bell or Horn.

The built-in tracks are:

  • Bell — track 202.
  • Horn — uses three tracks:
    • 211 — horn start
    • 212 — horn sustain
    • 213 — horn release
  • Cab Chatter — starts at track 300.

Cab Chatter behaves differently from Bell and Horn. While it remains ON, PMT schedules another chatter sound after a randomly selected delay of 30, 40, 50, 60, 70, 80, or 90 seconds.

What about my own sounds?

  • Audio Custom — plays your selected track once.
  • Audio Custom Replay — continuously loops your selected track while the control is ON.

Those patterns let you select an Audio Track from 1 through 9999.

On the Pro and Standard locomotive throttles, supported audio controls can also display their own speaker/volume button.

How do I add my own sounds to PMT and attach them to a button in the app?

PMT lets you add your own WAV sounds and create a button for them on the throttle.

First, prepare your sound file using the recommended PMT format:

  • WAV
  • Mono
  • 22,050 Hz
  • Signed 16-bit PCM

Choose an unused track number from 1 through 9999. Avoid numbers already reserved for PMT's normal engine, horn, bell, brake, and cab-chatter sounds.

Example: 9000.wav

Copy the file into the active sound folder on the microSD card:

  • /diesel/9000.wav for a Diesel sound set.
  • /steam/9000.wav for a Steam sound set.

Then, in the PMT app:

  1. Open Configuration → Output Control.
  2. Tap Add Output.
  3. Give the button a name, such as Station Announcement.
  4. Choose Audio Custom to play the sound once, or Audio Custom Replay to keep repeating it until you turn it off.
  5. Set Audio Track to the number you used — for example, 9000.
  6. Save the configuration.

The new Output Control will then appear as a button on supported PMT locomotive throttles.

How do I create my own sounds like new horns and new prime movers?

You can create your own PMT sound set from recordings using an audio editor such as Audacity.

For best results, export each finished sound as:

  • WAV
  • Mono
  • 22,050 Hz
  • Signed 16-bit PCM

For a new horn, PMT uses three files:

  • 0211.wav — horn start
  • 0212.wav — horn sustain, which loops while the horn is held
  • 0213.wav — horn release

For a new diesel prime mover, create:

  • 0090.wav — engine startup
  • 0091.wav — engine shutdown
  • 0100.wav — idle
  • 0101.wav through 0108.wav — engine Notches 1 through 8

The idle and notch files should be clean, steady loops. If possible, use recordings of the actual locomotive holding each engine notch rather than making one recording simply louder for every notch.

Audacity can be used to select the useful part of a recording, trim it, convert it to mono, adjust the volume, and make the looping files repeat smoothly.

Place the finished files in the /diesel folder on the PMT microSD card using the exact filenames above. Replacing those files replaces the corresponding horn or prime-mover sounds for that sound set.

For Steam, open Configuration → Steam Chuff Rate Curve.

The graph lets you visually adjust how fast the chuffs play at different throttle speeds:

  • The bottom of the graph is Throttle %.
  • The side of the graph is Chuff Rate %.
  • The white circles are the adjustment points along the curve.
  • The numbered positions across the graph represent throttle speeds from very slow through full throttle.
  • PMT automatically fills in the values between those adjustment points.

Use the Throttle Speed control at the top of the screen to work through the speed range while watching the locomotive. Compare the sound to the actual wheel rotation and adjust the curve until the chuffs look and sound natural.

If the chuffs are too fast for the wheels, lower the chuff rate at that part of the curve. If they are too slow, raise it.

What is this screen actually changing?

You do not have to manually edit Configuration Variables. This screen is a graphical editor for the chuff-rate CVs and modifies the CV values behind the scenes for you:

  • CV98 stores the low-speed points at 1, 5, 10, 15, 20, and 25% throttle.
  • CV99 stores the high-speed points at 35, 50, 65, 80, 90, and 100% throttle.

The firmware interpolates between those points to create the complete chuff-rate curve. These settings change the chuff cadence only; they do not change locomotive motor speed.

PMT uses four chuff phases per wheel revolution—approximately 0°, 90°, 180°, and 270°—so the goal is to adjust the curve until those four exhaust beats visually match one wheel revolution as closely as possible.

PMT's documented synchronization is based on throttle speed, not a physical wheel sensor or encoder. You are therefore tuning the sound to visually match the locomotive's wheels.

How do I use a DFPlayer Mini with PMT?

PMT supports the DFPlayer Mini as a simple sound-effects player. It is intended for individually triggered sounds such as:

  • horn or whistle clips
  • bell clips
  • announcements
  • coupler sounds
  • air-release sounds
  • accessory sounds

It is not the full PMTPlayer locomotive-sound system. With DFPlayer selected, PMT does not use automatic startup, shutdown, idle/notch, or other locomotive lifecycle audio. The DFPlayer can also play only one sound at a time.

What do I need?

  • ESP32 running PMT
  • DFPlayer Mini
  • microSD card inserted in the DFPlayer Mini
  • speaker
  • common ground between the ESP32 and DFPlayer

The ESP32 does not read the DFPlayer's microSD card. The DFPlayer reads its own card and PMT tells it which numbered MP3 track to play.

Default wiring

PMT's default DFPlayer preset uses the same pins on the supported Classic ESP32 and ESP32-S3 boards:

DFPlayer Mini ESP32
RXGPIO21 — ESP32 TX
TXGPIO13 — ESP32 RX
BUSYGPIO14
GNDGND
SPK1Speaker terminal 1
SPK2Speaker terminal 2

The UART wires are crossed:

ESP32 GPIO21 TX → DFPlayer RX
ESP32 GPIO13 RX ← DFPlayer TX

The BUSY connection is important if you want a sound to replay continuously.

Prepare the microSD card

DFPlayer sounds are MP3 files stored in:

/mp3/

Use four-digit filenames:

/mp3/0001.mp3
/mp3/0002.mp3
/mp3/0042.mp3

PMT supports DFPlayer track numbers 1 through 9999.

Enable DFPlayer audio

The documented firmware setup is:

CV400=0
CV401=1
CV400=1

CV401=1 selects the DFPlayer backend and applies the normal DFPlayer pin preset.

  • Name: for example, Horn

  • Audio Track: 1
  • Direction: Both, Forward, or Reverse as desired

That plays:

/mp3/0001.mp3

For a sound that keeps repeating while the button is ON, use Audio Custom Replay.

If BUSY is not connected/configured, a replay request falls back to one-shot playback.

Important DFPlayer limitations

  • Audio Custom — play once
  • Audio Custom Replay — replay while active

DFPlayer is designed for simple FX-triggered MP3 playback rather than PMT's complete synchronized locomotive audio system.

For full diesel or steam audio—including startup/shutdown, diesel notches, Steam chuffs, bell/horn sequencing, and richer playback behavior—use the PMTPlayer/I²S audio system instead.

    └── ...

SD CARD

    ├── 0080.wav

    ├── 0301.wav

Check these details:

  • The folder must be named exactly diesel or steam.
  • The WAV files go inside that folder, not in the root of the SD card.
  • Filenames use four digits, such as 0090.wav, not 90.wav.
  • PMT WAV files should be mono, signed 16-bit PCM. 22,050 Hz is the recommended sample rate.
  • Cab chatter starts at 0300.wav and should be numbered continuously. If there is a gap, PMT stops discovering chatter tracks at that gap.
  • A missing, damaged, unsupported, unreadable, or excessively large WAV file can result in 4 flashes.

A good first troubleshooting step is to open the SD card on your computer and compare its folder/file layout to the examples above.

5 flashes — audio system did not start

Common causes include:

  • microSD card not detected
  • incorrect SD-card format
  • 64GB or 128GB card still formatted as exFAT instead of FAT32
  • incorrect SD or audio GPIO configuration
  • incorrect I²S amplifier wiring
  • insufficient memory or another audio-startup failure

A missing individual WAV file normally produces 4 flashes, not 5.

6 flashes — audio information could not be saved

PMT was able to read the WAV file, but could not save its generated audio information back to the SD card.

Check:

  • that the card is writable
  • SD-card connections
  • correct FAT16/FAT32 formatting
  • that the card did not become unavailable during startup

The board may still play sound during that boot.

Does this apply to every ESP32?

No. These startup error codes apply to the ESP32-S3 Standard and ESP32-S3-CAM boards. They do not apply to the Classic ESP32 in the same way.

The onboard LED can also be hidden by CV21:

  • CV21=0 — onboard LED always off
  • CV21=1 — normal LED behavior, including startup error codes
  • CV21=2 — LED hidden while BLE or WebSocket is connected

If you are troubleshooting startup flashes, use:

CV21=1

The error code flashes, pauses, and repeats until the board is rebooted.

How do I capture a diagnostic for a specific problem in PMT firmware?

You can capture a detailed firmware diagnostic log using the Terminal built into the PMT app.

1. Connect to the PMT device

  1. Open the PMT application.
  2. Connect to the PMT device normally.
  3. Let the app complete its normal connection and handshake.
  4. Open the Terminal.

2. Start diagnostic logging

Enter: 

D2

and press Send.

A successful response is: 

ACK:D2

D2 enables debug information and requests SD-backed diagnostic logging.

3. Reproduce the problem

With diagnostic logging running, reproduce the problem you are trying to troubleshoot.

For example, perform the action that causes the unexpected behavior so that it is captured in the log.

4. Retrieve the diagnostic log

When you are finished reproducing the problem, return to the Terminal and enter: 

D00

Then press Send.

On firmware 3.6.3 or newer, D00 stops and closes the current diagnostic log and sends the newest log back through the Terminal.

A successful log begins with something similar to: 

A:D00=BEGIN,42781

followed by the diagnostic log, and finishes with something similar to: 

A:D00=END,42781,2DE62638

Wait until you receive the A:D00=END... line before doing anything else in the Terminal.

Do not send another Terminal command while the log is being transferred. Other command responses use the same text channel and could become mixed into the diagnostic output.

Once the complete diagnostic output has been captured, include it with your post in the Poor Man's Throttle Forum, along with a description of the problem and what you were doing when it occurred.

A couple of important notes

  • D00 also turns off the diagnostic/debug logging started by D2.
  • The numbers in the BEGIN and END lines should contain the same byte count.
  • The final value on the END line is a CRC32 value that can help identify an incomplete or corrupted capture.
  • If you receive an ERR:D00=... response instead of the log, include that error when asking for help.
  • SD-backed logging depends on the hardware/configuration allowing the logging path. If SD logging cannot be activated, D2 can still enable debug event generation, but the normal D00 SD-log retrieval workflow may not be available.

  1. From the Scan screen, tap the gear button in the lower-left corner.
  2. Open the Debug section in Settings.

  1. Turn on BLE Debug Mode.
  2. The app arms BLE debug logging for the next app launch.

At this point, BLE logging has not started yet.

Perform the action that is giving you trouble, such as scanning for a PMT device, connecting to it, reproducing a connection failure, or repeating the action that normally causes the BLE problem.

  • BLE scan start, stop, cancellation, completion, and failures

  • scan counts and UI scan results

Why is there a large delay when I increase or decrease the throttle?

If you are using the Standard or Pro throttle, the delay may be intentional. PMT uses momentum so the locomotive does not instantly jump to every new throttle setting.

Instead, the motor gradually ramps toward the speed you selected. This makes operation feel more like a heavy train accelerating and slowing down rather than an on/off toy.

I want it to respond faster

Use Switcher Mode on the Standard/Pro throttle. Switcher Mode removes the heavier momentum effect and gives you a much more responsive throttle, which is useful for switching and precise low-speed movements.

You can also use the Novice throttle if you prefer simpler, more immediate control without the heavier momentum behavior.

So if you move the throttle from, for example, 20% to 60% and the locomotive takes time to reach 60%, that does not necessarily mean Bluetooth or the app is lagging. It may simply be PMT's selected motion style doing what it was designed to do.

If the locomotive still responds unusually slowly while using a more immediate throttle mode, then check the troubleshooting guide for other causes such as low-voltage limiting or motor/start settings.

How do I do firmware updates OTA (Over-The-Air) without needing to connect the hardware to my computer?

If you have a supported ESP32-S3 N16R8 or N8R8 Poor Man's Throttle, you can update its firmware wirelessly from the PMT app instead of connecting the ESP32 to your computer with a USB cable.

The device must already support OTA and must be connected to WiFi. OTA support was introduced with firmware 3.2.0 for supported ESP32-S3 throttle hardware.

To perform an OTA update:

  1. Connect to your PMT device normally.
  2. Make sure the PMT device is connected to WiFi.
  3. Open the device's Configuration screen in the PMT app.
  4. Select Flash Firmware.
  5. The app checks that the device supports OTA and that it is ready to update.
  6. Confirm that you want to install the firmware update.
  7. Leave the device powered on while the update runs.

Before the firmware transfer begins, PMT safely stops the throttle and prepares the OTA connection. Once the actual firmware transfer starts, the app reports progress from 0% through 100% in 10% steps.

While OTA is active, the ESP32-S3's onboard RGB LED alternates GREEN and PURPLE. This is normal.

Do not remove power while the firmware update is in progress.

After the transfer reaches 100%, the PMT device automatically disconnects and reboots. The app then reconnects to the device, authenticates again, verifies the firmware version that is actually running, refreshes the device configuration, and restores normal controls.

What firmware version does OTA install?

OTA installs the current catalog latest firmware for your detected ESP32-S3 hardware.

OTA does not provide a list of older firmware versions to choose from.

If you need to:

  • install a specific older firmware version,
  • recover a device after an unsuccessful update, or
  • update a Classic ESP32-WROOM device,

use the normal USB firmware installer instead.

If your ESP32-S3 is running firmware older than the version that introduced OTA support, you will need to use the USB installer to get onto an OTA-capable firmware first. After that, future supported updates can be performed wirelessly.

If the app reports that WiFi is unavailable, restore the device's WiFi connection before trying the OTA update again. If an OTA update repeatedly cannot be completed, use the USB installer as the recovery path.

What are CV's, how do I change/query them, and what do they mean?

CV stands for Configuration Variable. A CV is simply a numbered setting stored inside your PMT device.

CVs control things such as:

  • device name
  • motor-driver settings and GPIO pins
  • WiFi
  • sound and volume
  • lighting and outputs
  • battery monitoring
  • automation and other device behavior

Most CV settings are saved in the ESP32's non-volatile memory, so they remain set after the device is powered off.

The easiest way to work with CVs

Connect to the PMT device, open Configuration, and expand Configuration Variables.

From there you can get/query a CV to see its current value or set it to a new value. Many normal PMT configuration screens also change CVs for you behind the scenes, so you usually do not need to work with CV numbers directly.

For example, the Steam Chuff Rate Curve screen modifies its associated CV values graphically instead of requiring you to type the CVs yourself.

You can also use the Terminal

To read a CV:

CV33?

A response might look like:

A:CV33=64

To change it:

CV33=65

The device responds with the value it accepted.

How do I know what a CV means?

Always look up the CV in the Configuration Variables Reference before changing it. The reference tells you:

  • what the CV controls
  • which PMT device type it applies to
  • the allowed values
  • the default value
  • what changing it does

This is important because the same CV number can mean different things on different PMT firmware types. For example, the meaning of a CV on a locomotive Throttle is not always the same as that CV on a Turbine device.

For most users, use the regular Configuration screens whenever a setting is available there. Use the Configuration Variables screen or Terminal when you need an advanced setting, troubleshooting, or something that is not exposed elsewhere in the app.

More information: Configuration Variables Reference · Command Protocol Reference

What commands are available, how do I use them, and what do they mean?

PMT devices understand text commands. The PMT app normally sends these commands for you when you operate the throttle or change settings, but you can also send commands yourself from the built-in Terminal.

How do I send a command?

  1. Open the PMT application.
  2. Connect to your PMT device and let the normal connection complete.
  3. Open the Terminal.
  4. Type a command.
  5. Press Send.

The device will normally respond with a confirmation, a value, or an error.

For example:

V

asks for the firmware version.

Other common examples are:

Command What it does
VShow the firmware version
VVShow the exact firmware build
C?Show connection status
IP?Show the device's IP address
F25Throttle: move forward toward 25% speed
R25Throttle: move in reverse toward 25% speed
SQuick stop
BBrake stop
B25Apply a variable brake amount
FX3=1Turn Output/FX 3 on
FX3=0Turn Output/FX 3 off
CV33?Query CV33
CV33=65Set CV33 to 65
SS?Check automation/script status
SP0Stop a running automation/script

PMT also has commands for:

  • Automation/script recording and playback
  • WiFi and connection diagnostics
  • ESP-NOW communication between PMT devices
  • Audio testing and diagnostics
  • Debug logging
  • Configuration Variables
  • Firmware updates on supported hardware
  • Turbine control

What do the replies mean?

A successful command commonly returns something beginning with:

ACK:

A command that could not be accepted commonly returns:

ERR:

Queries may return the requested information directly. For example, CV33? may return:

A:CV33=64

Do all PMT devices use the same commands?

No. There is a shared group of commands used by multiple PMT devices, but some commands are specific to a particular firmware type.

For example, locomotive Throttle firmware understands motor commands such as F25, R25, and FX3=1, while Turbine firmware has its own output-control commands.

Always check the Command Protocol Reference before manually sending an unfamiliar command. It shows the exact syntax, what the command does, what response to expect, and which PMT device types support it.

For normal operation, you usually do not need to type commands yourself—the app's throttle and Configuration screens generate the appropriate commands behind the scenes. The Terminal is most useful for diagnostics, advanced configuration, testing, and troubleshooting.

More information: Command Protocol Reference · Configuration Variables Reference

Firmware Installation

Step 1

Which ESP32 board family do you have?

Choose Classic ESP32-WROOM-32 or ESP32-S3. If you choose ESP32-S3, the installer will ask whether the metal module is marked N16R8 or N8R8 before any firmware install controls are shown.

Not sure? Do not guess. Compare the board in your hand with the pictures before continuing.

Step 1A

Which ESP32-S3 module do you have?

Check the writing on the metal ESP32 module itself. Find N16R8 or N8R8 in the printed module designation. These modules use different flash sizes and different firmware.

If you cannot tell which version you have, try N16R8 first. If the firmware flashes but the throttle does not start normally, connect to, or work correctly with the Poor Man’s Throttle app, come back here and install the N8R8 version instead. A successful flash only means the firmware was written to the board; it does not guarantee that you selected the correct S3 version.

The boards can look nearly identical. The module marking, not the board color or USB connector, determines which S3 firmware you need.

ESP32-S3 wireless updates

Already running PMT on an S3? You may not need the USB cable.

Supported ESP32-S3 N16R8 and N8R8 throttle devices can install the catalog's latest firmware from the Poor Man's Throttle app when Wi-Fi is connected. OTA always targets the catalog latest; by default CV15=0 refuses an older catalog version, while CV15=1 explicitly permits that catalog downgrade. What happens next

Follow the installer one step at a time.

  1. Click the firmware install button above.
  2. Choose the USB/serial device that represents your ESP32 and connect to it.
  3. Confirm the installation.
  4. For a normal update, keep Erase device off/unchecked.
  5. Wait until ESP Web Tools says the installation has finished. Do not unplug the board while it is writing.
  6. Optional exact-build check: after reconnecting, send VV from the PMT terminal. The response identifies the installed firmware build.
Troubleshooting If the installer cannot start flashing
  • Confirm you are using a USB data cable, not a charge-only cable.
  • Close Arduino Serial Monitor and other programs that might already be using the ESP32 connection.
  • If the device connects but flashing does not begin, hold BOOT, start the install and select the device. Release BOOT when erasing/writing begins.
  • On Windows, the Classic ESP32-WROOM-32 commonly uses a CP210x USB-to-serial interface. If Windows does not create a usable port, you can open the Silicon Labs CP210x driver page.
